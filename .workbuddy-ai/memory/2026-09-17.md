## 新建 hub-agent：基于 CodeBuddy Agent SDK 的 Agent Web 应用

- 需求来自 scene「Agent Apps」，指定 skill `codebuddy-chat-web`（本地技能 `init-cbc-sdk-web`，模板位于
  `~/.workbuddy-ai/plugins/marketplaces/cb_teams_marketplace/plugins/codebuddy-chat-web/skills/init-cbc-sdk-web/templates`，
  必须用 `copy-template.sh` 复制模板，不要手写）。
- 用户要求先充分理解 kkhome 项目再决定 Agent 用途与落地位置，不要直接问。
- 选定用途：**Hub 工具顾问** —— 主站 ai-navigator 有 313 个工具 / 10 个分类但只能关键词检索，
  补一层「带着任务问该用哪个工具」的能力。数据源为真实目录，禁止编造工具名与网址；
  目录无匹配时如实说明并帮写许愿墙需求。
- 落地位置：`D:\kkhome\hub-agent`（子项目，非合并进主站）。

### 关键实现
- `server/agent-context.ts`（新增）：把目录 grounding 上下文强制追加到任意 Agent 提示词之后，
  目录缺失时降级为「未同步」提示而不是伪造数据。
- `server/index.ts`：新增 `GET /api/catalog`；只读工具（Read/Grep/Glob）自动放行，
  Write/Edit/Bash 一律拒绝；cwd 固定到项目根，保证能读到 `data/tool-catalog.md`。
- `scripts/sync-catalog.mjs` + `npm run sync:catalog`：从
  `../public/config/plugins.config.json#ai-navigator` 生成 `data/tool-catalog.json`（前端用）
  和 `data/tool-catalog.md`（Agent 用 Grep/Read 检索）。
- `src/config.ts`：应用名、内置 Agent 提示词（`BUILTIN_PROMPTS`）、引导问题（`SUGGESTED_PROMPTS`）。
- `src/hooks/useAgents.ts`：内置两个 Agent（工具顾问 default / 许愿墙助手 wish-writer），
  内置 Agent 不写入 localStorage，也不能被删除。

### 模板本身的坑（已修，升级依赖时可能复发）
- `src/utils/iconMap.ts`、`NewChatDialog.tsx` 里 lucide 图标的 Record 类型要写成 `Record<string, LucideIcon>`，
  原来写 `{ size?: number }` 会和 lucide 的 `LucideProps`（size 是 string|number）冲突。
- `server/db.ts` 的 `const db` 需要显式 `Database.Database` 类型，否则 composite 声明产出 TS4023。
- SDK 新版 result 消息字段是 `duration_ms` / `total_cost_usd`，模板写的 `duration` / `cost` 不存在；
  `tool_result` 不在 SDK 消息联合类型里，比较时要 `as any`。
- tdesign 新版：`Card` 不支持 `onClick`/`bordered`/`hoverShadow`，`Descriptions.Item` 改名 `Descriptions.DescriptionsItem`，
  `itemStyle/labelStyle/contentStyle` 不是合法 props（改用 `style`）。
- `@tdesign-react/chat` 间接依赖 `tdesign-icons-web-components`，模板没声明，vite build 会报 resolve 失败，
  已作为直接依赖装上（^0.3.9）。
- `tsconfig.node.json` 默认会把 server/*.js 编译进源码目录，已加 `"outDir": "dist/server"`。
