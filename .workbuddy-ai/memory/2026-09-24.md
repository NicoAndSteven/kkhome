## 动效层盘点 + anime.js 评估（只读，未改任何代码）

问：能否用 anime.js 替换全站所有组件。

**结论：说法有概念错位。anime.js 是动效引擎（tween/timeline），不是组件库 ——
它能替换的是"动效实现方式"，不是"组件"。** 建议只做"动效增强层"，不全量替换。

### 盘点数据（实测）

- 规模：67 个 `.tsx` + 23 个 `.ts`，27 个插件目录。
- 动效：`src/index.css` 共 2032 行，含 **40 个 `@keyframes`**、38 处 `animation:`、29 处 `transition:`。
- JS 驱动动效极少：`requestAnimationFrame` 仅 **1** 处、`IntersectionObserver` 3 处、
  `style.transform` 3 处 → **现有动效 ~95% 是纯 CSS**。
- anime.js **未安装**。

### 全量替换的具体代价（不是空泛担忧）

1. 性能方向是**降级**：CSS transform/opacity 动画走 compositor 线程，
   主线程再忙也不掉帧；本仓主线程已有 523KB JS + 音频合成 + canvas，改成 rAF 驱动会互相抢。
2. `prefers-reduced-motion` 现在是**一条 CSS 媒体查询全局生效**，
   改成 JS 后要散落到 40+ 处逐个判断 —— 正是"手写清单，漏了不报错"的模式。
3. **会打破 e2e**：`tests/homepage.spec.ts` 有 30+ 处断言绑在 CSS class / 时序上，
   例如 `.intro-stage` 可见→8s 内隐藏、`.intro-mark` 文本、`.ac-rail` attached、
   `.ac-dock-player` 尺寸、`[title="惩罚环节"]` 必须带 `bg-amber-100`。
   动效时序一改，这些立刻变脆。
4. `:hover` / `:focus` / 状态过渡**只能**留在 CSS，于是最终会同时存在两套动效系统 ——
   正好命中"同一件事两份实现"。

### anime.js 真正赢的场景（所以不是"不做"）

- **复杂编排 timeline**：`IntroStage` 现在把 `grid → scanline → ring → mark → copy`
  的时序硬编码在 CSS 的 `animation-delay` 里，而时长 `introDuration` 来自
  `site.config.json` —— 配置改不动 CSS。这是 anime.js 的正解。
- **动态列表 stagger**：`ai-navigator` 有 313 个工具、许愿墙卡片数是运行时数据，
  CSS 无法按运行时数量做 stagger。
- **可中断 / 可反向**的转场（路由切到一半改主意）。
- **draggable**（food 转盘改成拖拽拨动）、**spring 缓动**（v4 自带）、
  **SVG 线条绘制**（v4 `svg` 模块，可给 timeline 插件用）、
  **文本拆分**（v4 `text` 模块，可给斜切大字用）。

### anime.js 版本事实（从 npm registry 实取，勿凭记忆）

- 最新 **4.5.0**，`"type": "module"`，ESM named exports。
- 子路径导出：`./svg` `./text` `./scope` `./timeline` `./animation` `./draggable`
  `./waapi` `./easings` `./easings/spring` `./easings/cubic-bezier` `./utils` `./engine`。
- 自带 TS 类型（`dist/modules/index.d.ts`），可直接用于本项目 TS。
- **v4 API 与 v3 完全不同**（v3 是 `anime({...})` 全局对象；v4 是 `animate()` / `stagger()` /
  `createTimeline()` / `createScope()`）。网上大量教程仍是 v3，照抄会错。
- 注意 `waapi` 子模块可走 Web Animations API（compositor 友好），但核心引擎是 rAF 驱动。

### push 卡死的两个真凶（重要，下次直接用这套）

`git push` 在本机反复卡住，最后靠这套组合推成功：

```bash
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 \
    -c credential.helper= -c credential.helper=store push origin main
```

1. **代理**：`git config http.proxy` 写的是 `127.0.0.1:12334`，**该端口没在监听**。
   真正能用的是 `127.0.0.1:7897`（Clash 混合端口）。
   环境变量 `http_proxy=127.0.0.1:62068` 对 curl/wrangler 有效，但那个代理
   对 github.com 的 CONNECT 会 502。
   诊断手法：`curl -o /dev/null -w "%{http_code}" -x <proxy> https://github.com/<owner>/<repo>.git/info/refs?service=git-upload-pack`
   → 7897 得 200，其余 000。
2. **凭据助手**：`git config --show-origin --get-all credential.helper` 显示**两个**：
   - PortableGit 系统级 `helper-selector`（会弹 GUI，非交互环境下直接卡死）
   - 用户级 `store`
   用 `-c credential.helper=`（空值重置列表）再 `-c credential.helper=store` 只留 store 即可。
   `~/.git-credentials` 里有 github.com 的凭据。

另外：`git ls-remote` 走 GET 能通、`push` 走 POST 才卡 —— 别用 ls-remote 正常就断定网络没问题。
`curl -X POST .../git-receive-pack` 返回 401 说明网络通、缺的只是认证。

## git 代理配置修复（用户问：怎么改 http.proxy 指向 12334 的问题）

### 结论：改成 `http://127.0.0.1:7897`，**不要**留空走直连

**关键纠正：别以为"删掉代理走直连"就行。** 本机直连 github.com 实测 **0/5**
（每次约 24s 超时）；7897 实测 **13/14 成功、约 3s**。
（`curl` 直连曾拿到过一次 200/1.1s —— 那是运气，直连是间歇性的，不可依赖。）

已改 `D:/kkhome/.git/config`（**仓库级**，不是全局）：

```
[http]
	proxy = http://127.0.0.1:7897
[https]
	proxy = http://127.0.0.1:7897
```

带注释说明「必须指向活着的端口 / 不能留空 / 别挪到全局」。

### 三个事实纠正

1. **`12334` 是仓库级配置**（`D:/kkhome/.git/config`），不是全局。
   `git config --global --get http.proxy` 一直是空的。
   大概是某个早期会话把当时的临时代理端口写进了 repo config，会话一结束就烂了。
2. **全局 `~/.gitconfig` 里有个死配置**：`[htt] proxy = http://127.0.0.1:12450`。

## 五个真坑（都可复用）

1. **Vite 8 的 CSS minifier 是 LightningCSS，会吃掉手写的 `-webkit-` 前缀组合。**
   同时写 `backdrop-filter` 和 `-webkit-backdrop-filter`，产物**只剩 `-webkit-`**，
   标准属性被静默丢弃 → **Firefox 完全没有模糊**（Firefox 不认 `-webkit-backdrop-filter`）。
   **正确写法：只写标准属性，前缀交给 autoprefixer，并在 package.json 里配 `browserslist`。**
   修完产物里两条都在。已用真 Firefox 复验：`backdrop-filter: blur(4px)` ✓。
2. **`mx-auto` 加在 flex-column 的子元素上会取消 `align-self: stretch`。**
   `<nav class="mx-auto max-w-7xl">` 在 block 流里正常，但父级是 `flex flex-col` 时
   会**缩成内容宽度**（实测 1280 → 594px），logo 直接压到第一个链接上。
   修法：补 `w-full`。验证方式别只看截图，直接量 `logo右边缘 vs links左边缘` 的间距是否对称。
3. **React 的 `muted` prop 不保证落到 DOM property 上**，而浏览器 autoplay 只看 property
   → 视频静默不播、无报错。必须在 effect 里 `el.muted = true; el.defaultMuted = true`，
   再 `el.play().catch(()=>{})`（自动播放被策略拒绝不是错误状态）。
4. **TypeScript 7 删掉了 `baseUrl`**，`paths` 改成相对 tsconfig 自身解析。报 `TS5102`。
5. **npm 全局缓存 `D:\VuesoftFiles\nodejs\node_cache` 在沙箱外写不进去**，
   `npm install` 直接失败。修法：`npm install --cache <项目内>/.npm-cache`
   （hub-agent 早就这么干了）。

### 删除失败的真实原因（值得记）

`rm -rf` 在本环境被 **safe-delete 守卫**接管，改走 `genie-trash`。守卫是 **FAIL CLOSED** 的：
trash 失败就什么都不删，只打一行
`[safe-delete][SAFE_DELETE_FAIL_CLOSED] ... "reason":"trash-failed"`。

**我一开始误判成"Windows 长路径超限"——错的。** 连 24KB 的 `src/` 都删不掉，
说明跟路径长度无关。真实原因：**残留进程锁住了 `node_modules`**。

祸根是自己埋的：验证 dev server 时用了
`(timeout 25 npm run dev &)` —— `timeout` 只杀了 `npm` 包装进程，
**真正的 vite 子进程变成孤儿活了下来**，一直占着 `D:\velorah-hero\node_modules`。
杀掉 PID 后，同一条 `rm -rf` 立刻成功。

### 排查套路（下次直接抄）

1. 先别急着换删除方式，**先找占用进程**：
   `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` 看 `CommandLine`，
   里面出现目标路径的就是元凶。
2. **绝对不能 `taskkill /IM node.exe`** —— WorkBuddy 自己的插件（sheetagent 等）
   也是 node.exe，一起杀会把自己干掉。必须**按 PID 单独杀**，杀前核对 CommandLine。
3. 本次实测：4 个 node 进程里只有 2 个是 velorah 的（vite + 它的 npm 父进程），
   另 2 个是 WorkBuddy 插件。杀完剩 2 个，宿主正常。

### 两个工具环境坑

- **PowerShell 工具在本会话拿不到输出**（返回 `Command completed with exit code 0`，
  但 stdout 是空的）。可靠绕法：`Set-Content` 写到文件，再用 Read 工具读。
- **bash 里不能调 powershell**：被安全策略拦（"bypasses PowerShell security checks"），
  必须走 PowerShell 工具。所以上面那条排查只能分两步做。

### 结论性教训

**后台起服务时，`timeout` 包不住子进程。** 验证完必须显式按 PID 清掉，
否则会在文件系统上留下一个隐形锁，几十分钟后变成"莫名其妙的删除失败"。

## 修掉洗牌分布测试的 1% 假红率（commit f7c4ab3）

### 发现经过

上一轮我把 CI 那次 3 秒失败判成「运行环境偶发」，**错了**。
`curl -L` 能跟随重定向拿到 job 日志（urllib 不行，会 401），日志里写着：

```
not ok 13 - assignUndercoverRound distributes undercover role across all positions
location: tests/party-room-state.test.mjs:147
error: 'Shuffle bias detected! χ² = 11.59 > 11.34 (α=0.01, df=3)'
```

不是 npm、不是缓存、不是 runner。

### 定性：测试太严，不是实现有偏

写了探针（`.workbuddy-ai/shuffle-bias-probe.mjs`）跑 2000 次「1000 局」：

- 超临界值 18/2000 = **0.90%**（理论 α=1.00%）
- 平均 χ² = **3.060**（均匀分布 df=3 应为 3.000）
- 最大 χ² = 16.25

→ Fisher-Yates 实现是**无偏的**；是那条测试用 `Math.random()` 却断言必须落在
α=0.01 临界值内，天然有约 1% 假红率。

### 修法

固定种子（mulberry32，seed `0x5eed`）+ 样本 1000 → **100000 局**，阈值 11.34 → 20。

- 种子固定 → χ² 是确定值（实测 **2.091**），假红率 0
- 阈值 20 是按灵敏度选的：N=1e5 时 χ² ≈ 533333·d²，能抓约 0.6% 的偏
  （原来 α=0.01 只能抓约 4%）
- 另加粗检「每个位置都必须拿到过身份」，报错可读
- **只在测试内 stub `Math.random`，在 finally 里还原**，不动生产代码

### 变异验证（两个变异体都被抓住）

1. 去掉 Fisher-Yates → 粗检红：`position host never got the undercover role`
2. `j` 的范围写成 `length`（有偏但非退化，四个位置都拿到）→ 粗检过，卡方红：
   `χ² = 7592.13 > 20`

变异时先把 `partyRoomState.js` 复制到 `.workbuddy-ai/` 备份，验完 `cp` 回来，
再用 md5 核对（`7fa0d7b6e14e6ff6affdb46c916b2869`）+ `git diff` 确认无残留。

### 术语

用户会问「门禁指什么」—— 门禁 = `package.json` 里的 `check` 脚本
（`npm run check`）= lint + check:assets + check:data + test:unit + build + test:e2e，
在 CI 里由 `.github/workflows/ci.yml` 的 `quality-gate` job 执行。
它的作用不是"跑测试"，是**卡住 deploy-edge**：门禁不绿，部署 job 连启动机会都没有。

### anime.js v4 的坑（实测，别再踩）

1. **anime.js 不对 `clip-path: inset()` 做插值**。传

2. **anime.js 会覆盖元素原有的 CSS `transform`**。所以任何靠 transform 做居中/定位的元素，
